@config guide@
@This is the guide for this config detailing what each option does:


x96_CONTROL_WELLS: 96 plate level control well positions given as 0-indexed indices (e.g. 7,11 7,10 7,9)

STRIPE_LIMIT: two numbers, the first is the minimum horizontal stripe size at which a stripe is flagged up, the second is the minimum  vertical stripe size to flag up

STIPE_CHECK_LIMIT: The positivity rate (%) at which to check a plate for stripes

SOP_nVIC_ESCALATION_LIMIT & SOP_ROX_FAIL_LIMIT & SOP_PLOD_LIMIT: Two numbers, the first is the number of failures at which to escalate, the second is the escalation level (see SOP)

QNOS_WELLS: The 384-level wells into which the Qnostic Positive control is placed

PRIO_CODES: Priority barcode prefixes (e.g. AVA)

POOL_QUERY: The SQL query used to get the POOL IDs associated with a list of array codes

NON_PATIENT_CODES: Any barcode prefixes which are not patient barcodes (must include an empty prefix (, , ))

NEGCON_WELLS: The 384-level wells into which the Qnostic Negative control is placed

MM_RULE_MIN_ROX_MODIFIER: This number is taken away from the araya's HIGH_ROX value (defined in araya thresholds) to get the minimum ROX at which to check for MM-Only signals

MM_RULE_MAX_nVIC_MODIFER: This number is added to the araya's nVIC_NEGATIVE threshold to get the maximum nVIC at which to check for MM-Only signals

MM_RULE_FAM_TO_VIC_LIMITS: Two numbers which define the FAM / VIC range within which to flag up mastermix only signals

LY_EL_QUERY: SQL query which returns lysis and elution plates associated with certain wells on a 384-well plate

INSTRUMENTS_QUERY: SQL query which returns the instruments associated with plates

GRAPH_LINE_SIZE: The size of the threshold lines on the scatter charts

GET_FILES_WHERE: A section of an SQL query which is used to build a larger query to get araya files from the LIMS sweeper

GET_FILES_MAIN: The main body of the SQL query to get araya files from the LIMS sweeper

ESCALATION_REASONS: A list of selectable escalation reasons for plates in Pool Helper's dropdown menus

COMMENTS_QUERY: SQL query which gets LIMS comments from a list of plates

BUFFER_PREFFIX: A barcode prefix which is to be considered as a blank well

BATCHNAV_MAIN: Some HTML to create a list of links to different plates

BATCHNAV_ITEM: Small snipped of HTML to be inserted into BATCHNAV_MAIN

BARCODES_QUERY: SQL query which is used to get the barcode prefixes on POOL plates

ACCUPLEX_WELLS: The 384-level wells into which the Accuplex Positive control is placed@

@RESTAMP_QUERY@
@select distinct j.job_name
from vgsm.sweeper_log s, vgsm.blob_values b, vgsm.job_header j
where b.blob_id=s.archived_file_blob and s.original_filename like '%PipetteLog%' and s.log_time >= to_date('$from_date$','yyyy-mm-dd') and s.log_time <= to_date('$to_date$','yyyy-mm-dd')
and j.job_name=substr(UTL_RAW.CAST_TO_VARCHAR2(DBMS_LOB.SUBSTR(b.blob_field, 600,1)),
instr(UTL_RAW.CAST_TO_VARCHAR2(DBMS_LOB.SUBSTR(b.blob_field, 600,1)),'<PLATECODE>')+11,12)
and j.job_name in
( select j1.job_name from vgsm.job_header j1, vgsm.sweeper_log s1, vgsm.blob_values b1 where b1.blob_id=s1.archived_file_blob and s1.original_filename like '%PipetteLog%' and j1.job_name=substr(UTL_RAW.CAST_TO_VARCHAR2(DBMS_LOB.SUBSTR(b1.blob_field, 600,1)),
instr(UTL_RAW.CAST_TO_VARCHAR2(DBMS_LOB.SUBSTR(b1.blob_field, 600,1)),'<PLATECODE>')+11,12)
group by j1.job_name having count(*)>1 )
